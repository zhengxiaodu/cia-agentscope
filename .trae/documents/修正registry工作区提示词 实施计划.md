# 修正 registry.py 工作区系统提示词 实施计划

## 概要

[registry.py](file:///workspace/app/agents/registry.py#L149) 的 `create_agent` 在系统提示词尾部追加了一段关于工作区目录的说明，其中"用户所有附件（如果有）……已上传到该目录下"已不真实——"上传即解析"改造后，用户上传的文件被解析为文本内容直接注入提示词（`_UPLOAD_CTX_HEADER` 片段），不再写入沙箱工作区目录。需修正该提示词，避免误导模型去工作区目录找用户附件。

## 现状分析（Phase 1 探索结论）

- **提示词原文**（L149）：
  ```
  注意当前工作区目录是/data/workspaces/{session_id}，用户所有附件（如果有）以及所有的技能文件已上传到该目录下，你只能在该目录下读/写/编辑文件，绝不允许操作目录以外的文件！
  当你生成文件时，给文件起一个英文名，不要用中文名生成文件
  ```
- **事实核验**：
  1. 用户附件：已不写入工作区——解析内容经 `_load_upload_context` 注入 query（orchestrator_service.py），工作区目录下**不存在**用户上传文件 ✗ 提示词失实
  2. 技能文件：仍真实装载在 workspace（`list_skills` / skill loader 机制，registry.py L4"按工作区机制装载"）✓ 该部分保留
  3. 工作区目录路径、只允许该目录内读写、生成文件用英文名：均真实有效，保留
- 该提示词对**每个 agent** 的每次 `create_agent` 均生效（单/多 agent 路径共用）

## 具体改动

### [app/agents/registry.py](file:///workspace/app/agents/registry.py#L147-L149)

将 L149 的 system_prompt 拼接替换为：

```python
        agent = Agent(
            name=definition.name,
            system_prompt=definition.system_prompt
            + f"\n注意当前工作区目录是/data/workspaces/{session_id}，你的技能文件已装载到该目录下，你只能在该目录下读/写/编辑文件，绝不允许操作目录以外的文件！"
            + "\n用户上传的文件不会出现在工作区目录中：其内容已解析并直接附在用户问题里，请直接阅读使用，不要尝试在工作区中查找用户附件。"
            + "\n当你生成文件时，给文件起一个英文名，不要用中文名生成文件",
            ...
```

三段结构：
1. **工作区约束**（保留原有）：目录路径 + 技能文件已装载 + 读写范围限制——仅删去"用户所有附件（如果有）以及"这一失实部分
2. **新增附件说明**（一句话，正向引导）：附件内容在问题文本中、勿在工作区查找——替代原失实表述，防止模型因找不到附件而困惑或空转调用 Read/Glob 工具
3. **英文文件名约束**（保留原有）

## 假设与决策

1. 不删除整段提示词——工作区路径约束与技能文件说明仍然真实且必要（技能确实装载在 workspace）。
2. 新增的第二句不涉及"解析内容如何注入"的实现细节（如 `_UPLOAD_CTX_HEADER` 标记），只说"附在用户问题里"——与模型实际所见一致，且无附件时该句是通用说明、无副作用。
3. 保持单行拼接的现有代码风格，不引入常量提取（改动最小化）。
