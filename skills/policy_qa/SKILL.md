# 制度问答（Policy QA）

通过调用制度问答通用接口，将用户问题传入后端，阻塞返回**回答正文**与**段落级引用文档**。适用于制度条款查询、政策解读、合规要求检索等场景。

**重要**：知识库 ID 列表由系统根据当前用户权限自动填充，调用方无需（也无法）指定。模型只需传入用户问题文本。

---

## 1. 何时调用

- 用户提出制度、政策、法规、规范类的具体问题，且明确或隐含需要从知识库中检索答案时
- 用户需要获取回答所依据的原文出处（文件名、页码、分片内容）时
- 用户需要多知识库联合检索回答时（系统会自动根据权限组合多个知识库）

### 不适用场景

- 通用百科知识问答（无需知识库检索）
- 需要多轮对话上下文的问答（本接口无状态）
- 流式输出场景（本接口为阻塞返回）

---

## 2. 工具信息

| 项目 | 说明 |
|------|------|
| **工具名称** | `policy_qa` |
| **调用方式** | 阻塞（Blocking）：等待完整回答返回，不流式 |
| **鉴权方式** | 无（内网服务间调用，知识库 ID 由系统自动填充） |
| **是否落库** | 否：不建会话、不保存消息，无状态调用 |
| **建议超时** | ≥ 60s（检索 + 模型生成需数秒） |

---

## 3. 工具参数

### 入参

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question` | `string` | 是 | 用户问题文本，至少 1 个字符 |

> **说明**：知识库 ID 列表由系统根据当前用户的智能体权限自动映射并填充，模型无需也无法指定。用户拥有的制度问答类智能体权限决定了可检索的知识库范围。

### 调用示例

```
用户: 入网机构需要满足哪些技术要求？
Agent: 调用工具 policy_qa，传入 question="入网机构需要满足哪些技术要求？"
```

---

## 4. 返回格式

工具返回一段格式化文本，包含**回答正文**与**引用来源**两部分：

```
入网机构应当具备以下技术条件：（一）具有安全可控的网络环境……

--- 引用来源 ---
[1] 入网机构管理办法 p12-13 [机构准入制度库]
[2] 网络安全管理办法 p5-6 [网络安全制度库]
```

### 回答正文

- 正常情况：返回基于知识库检索生成的回答正文
- 未检索到相关内容时：返回固定文案 `"未检索到相关内容，无法回答。"`，无引用来源
- 无权限时：返回 `"您没有制度问答权限，请联系管理员开通。"`

### 引用来源

每条引用包含：
- `[position]`：排序位置（与正文中的 `[1]` 序号对应）
- 文件名
- 页码范围（`p起始-结束`，仅 PDF 有）
- 知识库名称（方括号内）

---

## 5. 错误处理

| 场景 | 返回内容 |
|------|---------|
| 问题为空 | `"错误：问题不能为空。"` |
| 用户无制度问答权限 | `"您没有制度问答权限，请联系管理员开通。"` |
| 接口超时 | `"制度问答请求超时，请稍后重试。"` |
| 网络异常 | `"制度问答网络异常: {详情}"` |
| 接口返回非 200 | `"制度问答接口返回错误: HTTP {状态码} - {响应体}"` |

工具内部捕获所有异常，不会向 Agent 抛出错误，始终返回友好的文本提示。

---

## 6. 使用要点

1. **阻塞语义**：单次请求约需数秒，调用方需设置合理超时（系统已配置 120s）
2. **权限驱动检索**：知识库范围由用户权限决定，无需也无法手动指定知识库 ID
3. **多库联合召回**：用户拥有多个制度问答权限时，系统自动多库联合召回并统一生成回答
4. **引用即证据**：返回的引用来源为回答所依据的原文分片，可按序号与正文对应展示
5. **无状态**：本工具不建会话、不保存消息；如需留存问答记录，请自行保存回答与引用
6. **未命中处理**：当回答为 `"未检索到相关内容，无法回答。"` 且无引用来源时，表示知识库中无相关内容
7. **必须调用工具**：回答制度类问题时必须调用 `policy_qa` 工具，不要凭模型自身知识回答制度条款细节
